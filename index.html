Teaching AI to complete web forms

STAD68 final paper, 2026

A browser-automation study improved its test-task score by 5.4%.

The validation-task score improved by 9.1%.

The study used 1,240 browser form tasks.

These are benchmark results, not measured production savings.

Methods and full results

Browser-in-the-Loop: Reinforcement Fine-Tuning LLM Agents for Web Form Filling

Question: can browser feedback improve a language-model agent beyond copying demonstrations? The study uses FormFactory tasks that require a model to generate an executable plan, fill real form fields, and submit the form.

Method: QLoRA-tuned Qwen3-8B on 992 demonstrations, then ran online GRPO against live Chromium forms. The reward combines submission, field accuracy, and execution completeness. Group-relative comparisons avoid a separate critic model.

Finding: supervised initialization was necessary. Without it, GRPO did not discover the structured action format and produced zero reward. Reduced learning rate, early stopping, and data shuffling improved the supervised baseline before reinforcement learning.

Testing whether AI plans actually work

STAD80 paper, 2026

A 2026 course paper found that well-formatted AI plans could still fail when a browser executed them.

One tested model completed 11/124 tasks exactly, or 8.9%.

Another model completed 0/124 tasks when it used its most likely outputs.

Randomized outputs for that model achieved 76.6% to 87.9% correct formatting, not proof of successful browser execution.

Methods and full results

Concentrate or Collapse: When Reinforcement Learning Meets Diffusion Language Models for Web Planning

Question: do diffusion language models produce browser plans that succeed when executed, or merely plans that parse correctly? The study compares Qwen3-8B, ReFusion-8B, and FS-DFM-1.3B on 1,240 FormFactory tasks.

Method: compared supervised fine-tuning and reinforcement-learning variants using exact completion (Pass@1), parser validity, full browser execution, and average reward. Greedy and stochastic decoding expose different failure modes.

Finding: ReFusion reached 8.9% Pass@1 under MDPO, while FS-DFM remained at 0/124 under greedy decoding despite high stochastic parser validity. Valid syntax and shaped reward did not guarantee exact browser completion.

Impact: exposes policies that look competent under shaped reward but fail exact browser execution, reducing deployment risk.

How I built it

Context Atlas

Manifest V3 Chrome extension. Local Laya search with optional cloud Jev ranking.

Context Atlas finds the exact sentence that answers a question about the current page, then highlights it in place. Local search runs Laya through ONNX Runtime Web with WebGPU and a WASM fallback. Cloud search sends only bounded passages to Jev and returns source-linked matches.

  • Default local mode keeps page text on the device.
  • Cloud mode limits input to 400 query characters and 160 passages.
  • History stores hashed page identity, not raw page text or URLs.
  • 72 Python and 96 JavaScript tests cover routing, fallback, and packaging.

Impact: private page search by default, lower cloud inference for routine queries, and auditable answers tied to visible source text.
